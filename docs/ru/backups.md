# Резервные копии

English: [../backups.md](../backups.md)

У Netoryx два вида резервных копий:

- **копии базы данных** (ниже на этой странице): пользователи, подписки, платежи, настройки, тексты. Делаются
  автоматически, небольшие, отправляются в Telegram. Учётные записи в панелях восстанавливаются по базе Netoryx, потому
  что именно она — источник истины;
- **полная копия сервера** (`netoryx backup --full`, см. [Полная копия сервера](#полная-копия-сервера-и-переезд-на-другой-сервер)):
  всё, что нужно установке, сделанной установщиком, включая данные VPN-панели, сертификаты и секреты. Делайте её перед
  рискованными изменениями и для переезда на другой сервер.

## Автоматические копии

Включены по умолчанию (`BACKUP_ENABLED=true`), каждый день в `BACKUP_TIME` (04:00 по `TZ`). Каждая копия пишется в
`BACKUP_DIR` (`data/backups`, то есть `/app/data/backups` в томе `app-data` контейнера приложения); хранятся последние
`BACKUP_KEEP` файлов (7), а сам файл отправляется в чат Telegram `BACKUP_CHAT_ID` (по умолчанию первому администратору).

Задайте `BACKUP_PASSWORD`, чтобы шифровать копии (вывод ключа scrypt, AES-256-GCM). **Сделайте это**: копия содержит данные
клиентов и зашифрованные секреты и проходит через Telegram. Храните пароль отдельно от копий; потерянный пароль делает
копию нечитаемой.

Два формата, оба сжаты gzip:

- логический (`.jsonl.gz`): каждая таблица строками JSON. Работает с SQLite, PostgreSQL и MySQL и восстанавливается в любую
  из них, поэтому подходит и для переезда между базами;
- снимок SQLite (`.sqlite.gz`): быстрая согласованная копия для установки на SQLite.

Зашифрованные файлы заканчиваются на `.enc`.

## Сделать копию сейчас

```bash
sudo netoryx backup
```

или раздел **Backups** в веб-админке.

## Восстановление

Восстановление **заменяет все текущие данные**. Нужны файл копии и, если он зашифрован, пароль.

```bash
cd /opt/netoryx
docker compose cp /path/to/<backup file> app:/app/data/backups/
docker compose stop app
docker compose run --rm app /app/.venv/bin/python -m app restore /app/data/backups/<backup file> --yes --password '<password>'
docker compose up -d app
```

`--password` можно опустить, если `BACKUP_PASSWORD` задан в `.env`. Восстановление выполняется одной транзакцией; после него
приложение приводит панели к восстановленному состоянию. На новом сервере сначала выполните установку, затем восстановление.

## Полная копия сервера и переезд на другой сервер

```bash
sudo netoryx backup --full            # пишет /root/netoryx-backups/netoryx-full-<дата>.tar.gz
sudo netoryx backup --full /mnt/disk  # или в другой каталог
```

В архиве база данных и все тома установки (VPN-панель с ключами и клиентами, сертификаты), `.env`, собственные файлы
сервера в `deploy/` (сайты Caddy, таблица маршрутов HAProxy, сертификаты панели) и учётные данные из `/root/netoryx`. Кода
в архиве нет: он берётся из репозитория. Пока копируются тома, сервисы ненадолго останавливаются, поэтому открытые
VPN-соединения обрываются и переподключаются. `netoryx uninstall --purge` не удаляет `/root/netoryx-backups`.

Архив не зашифрован и содержит пароли и ключи: храните его в тайне (права `600` выставляются) и скопируйте за пределы
сервера, например `scp root@<сервер>:/root/netoryx-backups/netoryx-full-*.tar.gz .`.

Восстановление, на том же сервере или на новом:

1. На новом сервере установите Netoryx с **той же панелью**, что и на старом (`--panel ...`); ответы установщика не важны,
   восстановление их заменит.
2. Скопируйте архив на сервер и выполните `sudo netoryx restore /root/netoryx-full-<дата>.tar.gz`. Команда проверит архив
   (только ожидаемые файлы, та же панель), спросит `yes` и вернёт всё на место; `--yes` отключает вопрос.
3. Если адрес сервера изменился, направьте DNS-запись домена на новый сервер. Ссылки клиентов продолжат работать: домен,
   ключи Reality и идентификаторы клиентов те же.

Если копия сделана более новой версией, чем установленная, после восстановления выполните `sudo netoryx update`.

## Хорошие привычки

- Копируйте резервные копии за пределы сервера (копия в Telegram подходит; локальный том не переживёт потерю сервера).
- Делайте ручную копию перед каждым обновлением, а полную (`netoryx backup --full`) — перед переездом или переустановкой.
- Один раз проверьте восстановление на тестовой машине.
- Храните копию `/opt/netoryx/.env`: в нём `SECRET_KEY` и пароль базы данных.
