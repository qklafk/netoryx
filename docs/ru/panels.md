# Панели, локации и эндпоинты

English: [../panels.md](../panels.md)

Netoryx сам не передаёт трафик. Он создаёт и обновляет аккаунты на VPN-панелях и собирает ссылку подписки, которую
импортируют клиенты. Источник истины - база данных: фоновая задача приводит каждую панель к ней, поэтому панель, которая
была недоступна, догоняет состояние, когда возвращается.

Три понятия:

- **Панель (panel)**: одна установка 3x-ui, Remnawave и т. д. с её учётными данными.
- **Локация (location)**: то, что видит клиент («Германия», флаг). Локация группирует инбаунды.
- **Эндпоинт (endpoint)**: одна запись в подписке для инбаунда: адрес и порт, к которым клиент реально подключается, плюс
  необязательные переопределения ссылки (SNI, отпечаток и т. д.). У одного инбаунда может быть несколько эндпоинтов
  (прямой, через реле, через CDN).

Всё ниже делается в веб-админке: **Panels**, **Locations**, **Endpoints** (`https://<domain>/admin`). Те же операции есть в
админском API под `/api/admin`.

## Добавление панели

**Panels > Add**. Выберите тип, введите URL и учётные данные, оставьте включённой «проверку подключения». Панель проверяется
до сохранения. Учётные данные хранятся зашифрованными ключом `SECRET_KEY`.

| Тип | URL | Учётные данные | Примечания |
|---|---|---|---|
| 3x-ui (`xui`) | полный URL панели, включая секретный базовый путь, например `https://host:2053/abc123` | логин и пароль или Bearer API-токен (3x-ui 3.1+, предпочтительно) | Поддерживаются оба поколения API. Существующие инбаунды импортируются при добавлении. Для панели на том же сервере используйте `http://host.docker.internal:2053/<path>` с отключённой проверкой TLS. |
| Remnawave (`remnawave`) | `https://panel.example.com` или `http://remnawave:3000`, если он в той же Docker-сети | API-токен | 3.0+. Опции: `squad_uuids` (список; пусто = все), `username_prefix` (по умолчанию `tg_`), `direct` (по умолчанию true; добавляет заголовки `X-Forwarded-*` при прямом обращении к контейнеру). |
| Marzban (`marzban`) | URL панели | логин и пароль администратора | Существующих пользователей можно импортировать. |
| Marzneshin (`marzneshin`) | URL панели | логин и пароль администратора | Marzneshin сохраняет удалённых пользователей (мягкое удаление), поэтому то же имя пользователя повторно создать нельзя. Ссылки клиентов берутся из подписки панели в формате «links». |
| PasarGuard (`pasarguard`) | URL панели | API-ключ с правами чтения пользователей и системы | Ссылки клиентов берутся из подписки панели в формате «links». |
| Hiddify (`hiddify`) | URL панели **вместе с** настроенным админским прокси-путём | API-ключ | Hiddify Manager API v2. |

Общие `options` (JSON): `headers` (дополнительные HTTP-заголовки для каждого запроса, например `X-Api-Key` обратного прокси) и
`cookies` (для панели за прокси, защищённым cookie).

Для 3x-ui кнопка **Refresh inbounds** заново читает инбаунды панели: новые импортируются (вы выбираете, станут ли они
активными, в какую локацию попадут и по какому адресу подключаются клиенты), удалённые деактивируются. Состояние панелей
проверяется каждые несколько минут (`HEALTH_CHECK_INTERVAL_MIN`), а администраторы получают оповещение после
`HEALTH_FAILURES_BEFORE_ALERT` неудач.

**Импорт существующих пользователей.** Предпросмотр импорта показывает существующие аккаунты панели (срок, лимиты, трафик) и
принимает их, не меняя учётные данные и счётчики, так что текущие ссылки продолжают работать. Принятые аккаунты привязываются
к пользователям Telegram через ссылки-приглашения (действуют 30 дней).

## Локации и эндпоинты

1. Создайте локацию (название, флаг).
2. Поместите каждый активный инбаунд в локацию и добавьте для него эндпоинт. Адрес - это хост, к которому подключаются клиенты.
3. Проверьте предпросмотр ссылки в форме эндпоинта: он показывает ровно то, что получит клиент.

Виды эндпоинтов:

| Вид | Назначение |
|---|---|
| `direct` | Собственный адрес и порт инбаунда. |
| `relay` | Проброс порта или L4-реле перед настоящим сервером: отличаются только адрес и порт. Используйте для каскада (входной сервер в одной стране, выходной в другой) или чтобы дать сетям с ограниченным доступом другой путь к тому же инбаунду. |
| `cdn` | TLS/XHTTP/WebSocket через CDN; SNI, host, path, ALPN и т. д. переопределяются. |

Профили эндпоинтов: `standard` получают все. Записи `whitelist` - это профиль «LTE» для мобильных сетей, которые пропускают
только одобренные адреса (обычно реле внутри страны, чей адрес входит в разрешённый список оператора и пересылает трафик на
ваш настоящий сервер). В названии они получают суффикс «LTE», а для v2RayTun - `network-filter`, чтобы они появлялись только в
мобильной сети. По умолчанию они входят в общую подписку; задайте `SUB_WHITELIST_SEPARATE_URL`, чтобы отдавать их только по
`/sub/<token>/wl`. Релейный эндпоинт, не прошедший проверку здоровья, автоматически скрывается из подписок и возвращается,
когда восстанавливается.

`overrides` - это JSON-объект, применяемый к сгенерированной ссылке: `security`, `sni`, `host`, `path`, `alpn`, `fp`, `mode`,
`extra`, `serviceName` и `support-x25519mlkem768`. Переопределение сильнее значений по умолчанию (включая
`REALITY_COMPACT_HELLO`).

## Reality на порту 443 с собственным именем

Многие сети режут или замедляют нестандартные порты, поэтому Docker-стек собирает всё на 443. HAProxy `edge` читает
TLS-имя сервера каждого соединения и передаёт его дальше без изменений:

- имена из `deploy/haproxy/sni.map` уходят в `reality` (инбаунд 3x-ui на `REALITY_PORT`) или `tgproxy` (необязательный
  устаревший прокси для Telegram);
- любое другое имя уходит в Caddy (веб-админка, Mini App, подписки).

Самая надёжная схема Reality - «self-steal»: инбаунд заимствует настоящий сайт на вашем сервере, поэтому имя, сертификат и
IP-адрес совпадают.

1. Caddy уже отдаёт `vpn.<domain>` на `127.0.0.1:8444` с настоящим сертификатом.
2. В **Panels** создайте инбаунд Reality на панели 3x-ui (форма создаёт новые ключи X25519): порт = ваш `REALITY_PORT`
   (задаётся в `.env`, по умолчанию `8443`; он должен лишь быть свободен на хосте), SNI = `vpn.<domain>`, назначение =
   `127.0.0.1:8444`.
3. Добавьте `vpn.<domain> reality` в `deploy/haproxy/sni.map` и перезапустите `edge` (`docker compose restart edge`: это рвёт
   открытые VPN-соединения, делайте это в спокойное время).
4. Создайте эндпоинт для инбаунда с адресом `<domain>` и портом `443`.

Без self-steal выберите в качестве SNI Reality популярный внешний сайт (форма предлагает список и может проверить, что ваш
сервер до него доходит) и внесите это имя в `sni.map`. Посетители `vpn.<domain>` в браузере видят обычную страницу.

Эти шаги описаны, чтобы вы могли повторить их для другого сервера или сменить имя; что установщик настраивает сам, смотрите в
[installation.md](installation.md).

## Несколько серверов

Добавьте панель каждого сервера, поместите её инбаунды в локацию, и каждый тариф сможет использовать их все. Ссылка подписки
тогда содержит по одной записи на каждый активный эндпоинт (общая ссылка), а бот также предлагает профили по серверам и
ссылки подписки по серверам (`SUB_SHOW_SERVER_PROFILES`, `SUB_SHOW_SERVER_SUBSCRIPTIONS`).

## Перезапуски

Перезапуск `edge`, `caddy` или контейнера 3x-ui рвёт открытые соединения. Большинство клиентов переподключаются сами, некоторым
нужно выключить и включить VPN. Переразвёртывание только приложения VPN-сессии не затрагивает. Изменение `ADBLOCK_ENABLED` или
выхода для YouTube один раз перезапускает Xray.
