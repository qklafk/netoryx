# Исходящие вебхуки

English: [../webhooks.md](../webhooks.md)

Бот может уведомлять внешние системы (CRM, аналитику, бухгалтерию, ваши скрипты) о бизнес-событиях: регистрациях, покупках,
продлениях, платежах, истекающих подписках и других. Каждое событие отправляется как подписанный HTTP-запрос `POST` с телом
в формате JSON.

Эндпоинты настраиваются в веб-админке: **Management → Webhooks** (владелец и администраторы).

## Добавление эндпоинта

1. Откройте **Webhooks → Add endpoint**.
2. Введите URL получателя. Принимаются только адреса `https://`, а хост должен разрешаться в публичный адрес: адреса из
   частных, loopback, link-local и других зарезервированных сетей отклоняются (проверка повторяется при каждой доставке).
   В режиме разработки (`DEV_MODE=true`) допускается и обычный `http://localhost`.
3. Выберите события: `*` для всех, точные типы (`purchase, renewal`) или префикс (`payment.*`).
4. Сохраните и **скопируйте секрет подписи** (`whsec_...`). Он показывается один раз; если потеряли, используйте
   **Rotate secret**, старый секрет перестанет работать сразу.
5. Нажмите **Test**, чтобы отправить событие `webhook.test` и увидеть ответ получателя.

## Формат запроса

```
POST /your/path HTTP/1.1
Content-Type: application/json
X-Webhook-Id: evt_q3Jw0T9n0m6m3uYxP1c2ZxXy
X-Webhook-Event: purchase
X-Webhook-Timestamp: 1762700000
X-Webhook-Signature: sha256=5d2c...e9

{"id":"evt_q3Jw0T9n0m6m3uYxP1c2ZxXy","type":"purchase","created_at":"2026-11-09T12:00:00.123456+00:00",
 "user_id":123456789,"amount_kop":19900,"data":{"days":30,"plan_id":2,"kind":"purchase", "...": "..."}}
```

| Поле         | Значение                                                                                |
|--------------|-----------------------------------------------------------------------------------------|
| `id`         | Идентификатор события. Один и тот же id уходит при каждом повторе и ручной повторной доставке: по нему убирайте дубли. |
| `type`       | Тип события (список ниже).                                                              |
| `created_at` | Когда произошло событие, ISO 8601 в UTC.                                                |
| `user_id`    | Telegram ID пользователя или `null`.                                                    |
| `amount_kop` | Сумма в копейках (1 ₽ = 100) или `null`.                                                |
| `data`       | Детали события (id тарифа, платёжная система, дни и т. д.).                             |

В теле никогда нет секретов, токенов доступа, ссылок подписки и ключей VPN.

## Проверка подписи

`X-Webhook-Signature` - это `sha256=` и шестнадцатеричный HMAC-SHA256 от строки `"{timestamp}.{raw body}"` с секретом
эндпоинта в качестве ключа. Всегда проверяйте подпись по **исходному** телу запроса и отклоняйте старые метки времени,
чтобы исключить повторы.

```python
import hashlib
import hmac
import time

SECRET = "whsec_..."  # from the web admin


def verify(body: bytes, timestamp: str, signature: str, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    expected = "sha256=" + hmac.new(SECRET.encode(), timestamp.encode() + b"." + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)


# Flask example
from flask import Flask, abort, request

app = Flask(__name__)


@app.post("/webhooks/vpn")
def receive():
    if not verify(request.get_data(), request.headers["X-Webhook-Timestamp"], request.headers["X-Webhook-Signature"]):
        abort(401)
    event = request.get_json()
    # ... process event["type"], deduplicating by event["id"] ...
    return "", 204
```

## Доставка и повторы

- Доставка считается успешной, если получатель ответил любым статусом `2xx` в течение 10 секунд. Редиректы не
  выполняются; тело ответа игнорируется.
- События пишутся в исходящую очередь вместе с изменением, которое их породило, поэтому ничего не теряется при
  перезапусках и ничего не отправляется для откатённых изменений. Обычно доставка уходит примерно за 15 секунд.
- Неудавшаяся доставка повторяется через **1 мин, 5 мин, 30 мин, 2 ч, 6 ч и 24 ч** (всего 7 попыток). После этого она
  помечается как `dead`.
- Доставки могут приходить повторно и не по порядку: убирайте дубли по `id` и сравнивайте `created_at`.
- После нескольких подряд `dead`-доставок (настройка **Outgoing webhooks → Disable an endpoint after N failed deliveries in
  a row**, по умолчанию 3, `0` = никогда) эндпоинт отключается, а администраторы получают уведомление. Исправьте получателя
  и включите эндпоинт снова; отдельные события можно отправить повторно в **Deliveries**.
- История доставок хранится по умолчанию 14 дней (настройка **Keep delivery history, days**).

## Типы событий

| Тип                         | Когда                                                  |
|-----------------------------|--------------------------------------------------------|
| `user.registered`           | Новый пользователь запустил бота                       |
| `consent.accepted`          | Пользователь принял условия                            |
| `trial.started`             | Выдана пробная подписка                                |
| `purchase`                  | Куплен тариф (новая подписка или продление)            |
| `renewal`                   | Подписка продлена автоматически                        |
| `subscription.granted`      | Доступ выдан без покупки (администратором, подарком и т. д.) |
| `subscription.expired`      | Подписка истекла                                       |
| `subscription.auto_renew`   | Автопродление включено или выключено                   |
| `subscription.link_rotated` | Пользователь перевыпустил ссылку подписки              |
| `payment.succeeded`         | Платёж зачислен                                        |
| `payment.refunded`          | Платёж возвращён                                       |
| `payment.held`              | Платёжная система сообщила, что платёж получен, но удержан |
| `payment.repeat`            | Зафиксировано рекуррентное списание (автопродление)    |
| `payment.amount_mismatch`   | Оплаченная сумма отличается от суммы счёта             |
| `promo.redeemed`            | Использован промокод                                   |
| `gift.purchased`            | Куплен подарочный код                                  |
| `gift.redeemed`             | Подарочный код активирован                             |
| `referral.applied`          | Пользователь пришёл по реферальной ссылке              |
| `referral.reward`           | Начислено реферальное вознаграждение                   |
| `partner.transfer`          | Партнёрский доход переведён на основной баланс         |
| `withdrawal.requested`      | Партнёр запросил выплату                               |
| `withdrawal.paid`           | Выплата выполнена                                      |
| `invite.redeemed`           | Приглашение использовано                               |
| `ticket.created`            | Открыто обращение в поддержку                          |
| `webhook.test`              | Отправляется только кнопкой **Test**                   |
