# Настройка

English: [../configuration.md](../configuration.md)

У Netoryx два уровня настроек.

1. **Файл `.env`** (`/opt/netoryx/.env` после стандартной установки). Читается при запуске. В нём секреты, адреса и
   устройство процессов, и он задаёт *значение по умолчанию* для всех остальных настроек.
2. **Настройки времени выполнения** в веб-админке (**Settings**, `https://<domain>/admin/settings`) и в админском меню бота.
   Они хранятся в базе (секреты в зашифрованном виде) и применяются без перезапуска. Значение, изменённое там,
   переопределяет одноимённое из `.env`.

Что к какому уровню относится: настройка *только для окружения*, если она нужна до появления базы или описывает сам процесс
(`BOT_TOKEN`, `DATABASE_URL`, `SECRET_KEY`, `PUBLIC_BASE_URL`, `ADMIN_IDS`, `REDIS_URL`, `WEB_HOST`, `WEB_PORT`, `LOG_LEVEL`,
`ROLE`, `BACKUP_DIR` и устаревшие начальные значения `XUI_*` / `REMNAWAVE_*`). Админка показывает их только для чтения.
Всё остальное редактируется на лету, и в `.env` это можно вообще не указывать.

После правки `.env` применяйте её только к контейнеру приложения, это не прерывает VPN-сессии:

```bash
cd /opt/netoryx && docker compose up -d --no-deps app
```

Имена настроек в `.env` нечувствительны к регистру; списки пишутся через запятую (`ADMIN_IDS=1,2`). Деньги вводятся в рублях.
В `.env.example` в репозитории перечислены необязательные настройки с комментариями.

## Обязательные

| Настройка | Значение |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather. |
| `ADMIN_IDS` | Telegram ID владельцев через запятую. Они получают роль владельца. |
| `SECRET_KEY` | Шифрует хранимые секреты и подписывает токены. Создаётся установщиком; при ручной установке задайте его сами (Docker-стек без него не запустится). **Не теряйте и не меняйте его**: сохранённые пароли панелей и API-ключи станут нечитаемыми. Входит в любой план резервного копирования. |
| `DOMAIN`, `POSTGRES_PASSWORD` | Используются Docker-стеком (`docker-compose.yml`), чтобы получить `PUBLIC_BASE_URL` и `DATABASE_URL`. |
| `APP_MODE` | `shop` (продажа подписок, по умолчанию) или `personal` (приглашения и участники, без платежей). Позже переключается из админки. |

## Самые важные настройки

### Приватность и ссылки

| Настройка | По умолчанию | Значение |
|---|---|---|
| `CLIENT_IP_LOGGING` | `off` | `off` не хранит IP клиентов ни в логах, ни в базе; `masked` хранит только сеть (`203.0.113.x`); `full` хранит адреса целиком. Лимиты частоты и проверки IP платёжных систем работают в памяти при любом значении. См. [privacy.md](privacy.md). |
| `REALITY_COMPACT_HELLO` | `true` | Ссылки Reality просят у клиентов отпечаток Firefox без постквантовой части ключа, чтобы TLS-приветствие помещалось в один TCP-сегмент. Нужно в сетях, которые отбрасывают второй сегмент большого приветствия. Переопределение у эндпоинта в админке всё равно приоритетнее. См. [troubleshooting.md](troubleshooting.md). |
| `SUB_PROFILE_TITLE`, `SUB_ANNOUNCE`, `SUB_UPDATE_INTERVAL_HOURS` | название бренда, пусто, 12 | Что приложения показывают для подписки и как часто её обновляют. |
| `SUB_ROUTING_RU_DIRECT` | `false` | Добавляет профиль маршрутизации, отправляющий российские сайты и IP напрямую. |
| `SUB_JSON_ENABLED`, `SUB_JSON_AUTO`, `SUB_JSON_DIRECT_RU`, `SUB_JSON_DIRECT_DOMAINS`, `SUB_JSON_PROXY_DOMAINS` | `true`, `true`, `true`, пусто, пусто | Happ и v2RayTun получают JSON-подписку с конфигурацией Auto и российскими доменами напрямую. См. [subscriptions.md](subscriptions.md). |
| `SUB_WHITELIST_SEPARATE_URL` | `false` | Отдавать записи «LTE» только по `/sub/<token>/wl`, а не в основной подписке. |

### Устройства

| Настройка | По умолчанию | Значение |
|---|---|---|
| `XUI_DEVICE_LIMIT` | `hwid` | `hwid`: бот считает устройства по заголовку `x-hwid`, который присылают приложения вроде Happ и v2RayTun, а 3x-ui лимит не получает. `ip`: использовать `limitIp` из 3x-ui, который работает только при включённом журнале доступа Xray (в нём IP клиентов и посещённые сайты). |
| `HWID_REQUIRED` | `false` | Приложение без HWID: `false` всё равно обслуживает его, `true` показывает уведомление. |
| `HWID_DEVICE_TTL_DAYS` | `30` | Забывать устройства, не появлявшиеся столько дней (`0` = никогда). |
| `DEVICE_RESET_COOLDOWN_MIN` | `30` | Как часто пользователь может сбрасывать свои устройства. |

### Блокировки и маршрутизация на серверах 3x-ui

| Настройка | По умолчанию | Значение |
|---|---|---|
| `ADBLOCK_ENABLED` | `false` | Добавляет правило Xray, отправляющее `geosite:category-ads-all` в blackhole-аутбаунд на каждом сервере 3x-ui. Переключение перезапускает Xray, поэтому подключённые пользователи переподключаются. Рекламу внутри видео YouTube так заблокировать нельзя. Remnawave, Marzban и другие панели сами управляют своей конфигурацией Xray и не затрагиваются. |
| `YOUTUBE_EXIT_ENABLED` | `false` | Отправлять YouTube через отдельный выходной сервер (в стране, где YouTube не показывает рекламу). Если этот сервер недоступен, YouTube идёт обычным путём. Какие страны без рекламы, со временем меняется, поэтому рассчитывайте на «как получится». |
| `YOUTUBE_EXIT_LINK` | пусто | Ссылка выходного сервера: `vless://` (Reality или TLS), `socks5://user:pass@host:port` или `ss://`. |
| `YOUTUBE_EXIT_DOMAINS` | `geosite:youtube` | Домены для выхода; можно добавить `domain:googlevideo.com`. Требует sniffing на VLESS-инбаундах, который бот включает сам. |

### Прокси для Telegram

| Настройка | По умолчанию | Значение |
|---|---|---|
| `TG_PROXY_ACCESS` | `off` | Устаревшее. Кто получает личный прокси для Telegram: `everyone`, `subscribers` или `off` (см. [telegram-proxy.md](telegram-proxy.md)). |
| `TG_ONLY_ENABLED` | `true` | Общая ссылка «только Telegram» и её страница `/tg` ([telegram-only.md](telegram-only.md)). |
| `TG_ONLY_EXCLUDED_COUNTRIES` | `RU,BY,CN,IR,KP,TM,VN` | Серверы этих стран (по флагу локации) для неё не предлагаются. |
| `TG_ONLY_ALLOW_UNKNOWN_COUNTRY` | `false` | Предлагать и серверы, у локации которых нет флага страны. |
| `TG_ONLY_MONTHLY_LIMIT_GB` | `0` | Месячный лимит трафика общего клиента на сервер (0 - без лимита). |
| `TG_ONLY_DAILY_ALERT_GB` | `50` | Оповещать администраторов при суточном трафике общего клиента выше этого (0 - выключено). |
| `TG_SOCKS_ENABLED` | `false` | Устаревшее. Главный выключатель аккаунтов SOCKS5 (ничего не показывается, пока какой-либо `mixed`-инбаунд 3x-ui не помечен как инбаунд SOCKS5 для Telegram). |
| `TG_PROXY_MAX_SERVERS` | `2` | Прокси-серверов на пользователя (основной плюс резервные). |
| `TG_PROXY_ROTATE_COOLDOWN_MIN` | `60` | Как часто пользователь может получить новую ссылку прокси. |

Полное руководство: [telegram-proxy.md](telegram-proxy.md).

### Языки и веб

| Настройка | По умолчанию | Значение |
|---|---|---|
| `DEFAULT_LANGUAGE` | `ru` | Язык для новых пользователей. |
| `ENABLED_LANGUAGES` | `ru,en,uk,kk,uz,fa,zh` | Языки, которые могут выбрать пользователи; язык по умолчанию доступен всегда. |
| `CABINET_ENABLED` | `false` | Личный кабинет клиента в браузере по адресу `/cabinet`. Нужен HTTPS. Способы входа: `CABINET_LOGIN_BOT` (по умолчанию включён), `CABINET_LOGIN_TELEGRAM`, `CABINET_LOGIN_EMAIL` (нужны `SMTP_*`). См. [web-cabinet.md](web-cabinet.md). |
| `WEB_ADMIN_ENABLED`, `MINIAPP_ENABLED` | `true` | Выключают веб-админку или Mini App. |
| `WEB_SESSION_HOURS` | `24` | Длительность сессии веб-админки. |

### Бизнес-параметры по умолчанию

`TRIAL_DAYS` (3, `0` отключает пробный период), `TRIAL_DEVICE_LIMIT`, `TRIAL_TRAFFIC_GB`, `EXPIRY_REMINDER_DAYS` (`3,1`),
`AUTO_RENEW_HOURS_BEFORE`, `MIN_TOPUP_RUB`, `MAX_TOPUP_RUB`, `WELCOME_BONUS_RUB`, `REFERRAL_ENABLED`,
`REFERRAL_REWARD_MODE` (`days`, `balance`, `partner`), `REFERRAL_LEVELS_PERCENT` (`10` или `10,5,2` для нескольких уровней),
`WITHDRAWALS_ENABLED`, `GIFTS_ENABLED`, `WINBACK_ENABLED`, `REQUIRED_CHANNEL_ID` (обязательная подписка на канал),
`BRAND_NAME`, `SUPPORT_URL`, `CHANNEL_URL`, `TERMS_URL`, `PRIVACY_URL`, `LEGAL_CONSENT_REQUIRED`.
Ссылки принимают адреса `https://` и `tg://`; ссылка без схемы (`t.me/name`, `@name`) дополняется до `https://`.

Реферальные бонусы ждут первой полной оплаты приглашённого не меньше `MIN_TOPUP_RUB`: бонус пригласившему
(`REFERRAL_INVITER_REQUIRES_PAYMENT`) и бонус самому приглашённому в рублях (`REFERRAL_INVITEE_REQUIRES_PAYMENT`), оба
включены по умолчанию, поэтому новые аккаунты не могут собрать деньги, за которые никто не платил. При
`WINBACK_USAGE=once` (по умолчанию) скидка для возвращения действует на одну покупку, даже если со скидкой создано
несколько счетов.

Роли админов: `owner` (всё), `admin` (всё, кроме управления админами, восстановления из копии и секретов), `support`
(пользователи, тикеты, просмотр платежей; без бесплатных дней, изменения срока и лимитов — это право `subs_grant` у
админов) и `viewer` (только просмотр).

Тарифы, цены и тексты редактируются в админке (**Plans**, **Texts**); при первом запуске создаётся пример тарифа.

### Пользовательское соглашение и политика конфиденциальности

Опубликуйте собственные документы (шаблоны: [политика конфиденциальности](legal/privacy-policy-template.md),
[пользовательское соглашение](legal/terms-of-service-template.md)) по любому публичному URL и подключите их:

| Настройка | По умолчанию | Значение |
|---|---|---|
| `TERMS_URL` | пусто | Ссылка на ваше пользовательское соглашение или публичную оферту. Показывается на экране согласия и командой `/terms`. |
| `PRIVACY_URL` | пусто | Ссылка на вашу политику конфиденциальности. |
| `LEGAL_CONSENT_REQUIRED` | `false` | Просить каждого клиента принять документы перед использованием бота (нужен `TERMS_URL` или `PRIVACY_URL`). |
| `LEGAL_CONSENT_VERSION` | `1` | Измените (например, на `2`) после обновления документов, и все будут спрошены снова. |

Документы должны соответствовать вашей установке: если вы задали `CLIENT_IP_LOGGING` отличным от `off` или включили вход в
веб-кабинет по почте, укажите это в политике конфиденциальности.

### Эксплуатация

| Настройка | По умолчанию | Значение |
|---|---|---|
| `DELETE_ORPHAN_CLIENTS` | `false` | Удалять аккаунты на панелях, которые бот не создавал, но которые похожи на его собственные. Оставьте выключенным, если точно не знаете, что это нужно. |
| `EXPIRED_CLIENT_RETENTION_DAYS` | `30` | Удалять истёкшие аккаунты с панелей через столько дней. |
| `RECONCILE_INTERVAL_MIN`, `HEALTH_CHECK_INTERVAL_MIN` | `5`, `2` | Как часто панели приводятся к состоянию базы и проверяются. |
| `MONITOR_ALERTS_ENABLED` | `true` | Оповещения администраторам о высокой загрузке CPU, RAM или диска, остановленном Xray, недоступных нодах. |
| `BACKUP_*` | см. [backups.md](backups.md) | Ежедневные резервные копии. |
| `LOG_LEVEL`, `LOG_JSON`, `SENTRY_DSN` | `INFO`, `false`, пусто | Журналирование. |
| `UPDATE_CHECK_REPO` | пусто | `owner/name` на GitHub; тогда админка показывает, что вышел новый релиз. |
| `REDIS_URL` | пусто | Необязательно: хранилище FSM, ограничение частоты и блокировки, общие для нескольких процессов. |
| `TZ` | `Europe/Moscow` | Часовой пояс для бизнес-времени (напоминания, тихие часы, время резервного копирования). |

Платёжные настройки описаны в [payments.md](payments.md).

## Проверка конфигурации

```bash
cd /opt/netoryx
docker compose exec app /app/.venv/bin/python -m app check
```

Команда проверяет настройки, базу данных и токен бота. `--offline` пропускает обращение к Telegram.
