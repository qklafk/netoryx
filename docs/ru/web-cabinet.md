# Веб-кабинет

English: [../web-cabinet.md](../web-cabinet.md).

Веб-кабинет — это личный кабинет клиента в обычном браузере: тот же интерфейс, что и у Telegram Mini App
(подписка, подключение, тарифы, оплата, баланс, рефералы, поддержка), но без Telegram. Он нужен, когда Telegram
недоступен. Адрес кабинета: `https://<ваш домен>/cabinet/`.

## Что нужно

- `PUBLIC_BASE_URL` с HTTPS-адресом вашего домена (cookie сессии выдаётся с флагом `Secure`).
- Включить кабинет: `CABINET_ENABLED=true` (или в веб-админке: «Настройки» → «Веб-кабинет»). По умолчанию он выключен.
- Включён хотя бы один способ входа (ниже). Если используете обратный прокси, укажите его в `TRUSTED_PROXIES`, иначе
  лимиты попыток входа будут считаться по адресу прокси.

Адрес возврата после оплаты задаётся при запуске: после включения кабинета перезапустите приложение, тогда
платёжные системы будут возвращать клиента на нейтральную страницу `/pay/return` со ссылками в кабинет и в бота.
Оплата Telegram Stars в кабинете недоступна (она работает только внутри Telegram).

## Способы входа

Каждый способ включается отдельно.

### 1. Ссылка из бота (`CABINET_LOGIN_BOT`, по умолчанию включён)

В профиле бота появляется кнопка «Веб-кабинет» (также команда `/cabinet`; в Mini App — «Открыть в браузере»).
Бот выдаёт одноразовую ссылку `https://<домен>/cabinet/login/<токен>`, она действует 10 минут. Этот способ
работает, пока клиент может хотя бы один раз открыть бота (например, через VPN или прокси).

### 2. Telegram Login Widget (`CABINET_LOGIN_TELEGRAM`)

Клиент нажимает кнопку «Войти через Telegram» на странице входа. Чтобы она заработала:

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/setdomain`, выберите вашего бота и укажите домен
   (например, `vpn.example.com`) — тот же, что в `PUBLIC_BASE_URL`.
2. Включите `CABINET_LOGIN_TELEGRAM=true`.

Подпись данных проверяется по токену бота (HMAC-SHA256), данные старше 15 минут и повторно отправленные данные
отвергаются. Сам Telegram при этом должен быть доступен клиенту в момент входа.

### 3. Ссылка на e-mail (`CABINET_LOGIN_EMAIL`)

Клиент один раз привязывает адрес в кабинете (Профиль → Веб-кабинет → «E-mail для входа») и подтверждает его по
ссылке из письма. Дальше он вводит адрес на странице входа и получает письмо с одноразовой ссылкой. Ответ сервера не
зависит от того, известен ли адрес; число запросов ограничено на адрес и на IP.

Нужен SMTP-сервер:

| Параметр | Значение |
| --- | --- |
| `SMTP_HOST`, `SMTP_PORT` | сервер и порт (587 для STARTTLS, 465 для SSL) |
| `SMTP_SECURITY` | `starttls`, `ssl` или `none` |
| `SMTP_USERNAME`, `SMTP_PASSWORD` | учётные данные, если сервер их требует |
| `SMTP_FROM` | адрес отправителя, например `VPN <no-reply@example.com>` |

Чтобы письма не попадали в спам, настройте SPF и DKIM для домена отправителя.

## Сессии и безопасность

- Сессия живёт `CABINET_SESSION_DAYS` дней (по умолчанию 30), хранится в cookie `HttpOnly`, `SameSite=Lax`, `Secure`.
  В базе лежит только хеш токена.
- Изменяющие запросы требуют заголовок `X-CSRF-Token` и допустимый `Origin`.
- «Выйти» завершает текущую сессию, «Выйти на всех устройствах» — все сессии клиента.
- Заблокированный пользователь не может войти, а его открытые сессии перестают работать. В личном режиме входят
  только участники и администраторы.
- Устаревшие сессии и ссылки удаляются автоматически.
