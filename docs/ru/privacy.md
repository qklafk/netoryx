# Приватность: что хранит Netoryx и что не хранит

English: [../privacy.md](../privacy.md)

Netoryx устроен так, чтобы оператор VPN мог вести сервис, не собирая больше данных, чем нужно для бизнеса. Здесь описаны
значения по умолчанию этого релиза; код открыт, поэтому любое утверждение можно проверить.

## Что не хранится

- **IP-адреса клиентов.** При значении по умолчанию `CLIENT_IP_LOGGING=off` они не попадают ни в логи, ни в столбцы базы
  (журнал доступа веб-сервера, сессии веб-кабинета). Лимиты частоты запросов и списки разрешённых IP платёжных систем
  по-прежнему работают, только в памяти. `masked` сохраняет лишь сеть (`203.0.113.x`, для IPv6 - /48); `full` сохраняет адрес
  целиком. Выбирайте осознанно и, если выбрали что-либо кроме `off`, укажите это в политике конфиденциальности.
- **Посещённые сайты и содержимое трафика.** Netoryx их никогда не видит. Панели ведут счётчики трафика по аккаунтам (байты),
  этого достаточно для лимитов трафика.
- **Журнал доступа Xray.** Для лимита устройств он не нужен. При `XUI_DEVICE_LIMIT=hwid` (по умолчанию) бот не передаёт в 3x-ui
  лимит по IP (`limitIp`), поэтому журнал доступа Xray, где записываются IP клиентов и посещённые хосты, можно держать
  выключенным. Переход на `XUI_DEVICE_LIMIT=ip` требует этого журнала; делайте это, только если принимаете последствия.
- **Исходные идентификаторы устройств.** Значение `x-hwid`, которое присылают клиентские приложения, хранится только как
  HMAC-SHA256 с ключом, производным от `SECRET_KEY`. Исходное значение из базы прочитать нельзя, можно лишь проверить,
  встречалось ли данное значение. Устройства, не появлявшиеся `HWID_DEVICE_TTL_DAYS` дней (30), забываются.
- **Секреты в логах.** Токены, пароли и API-ключи не попадают в логи и журнал аудита. Сохранённые пароли панелей, API-ключи и
  пароли SOCKS5 шифруются ключом `SECRET_KEY`.

## Что хранится

- Telegram ID, имя пользователя и отображаемое имя, язык, реферальные ссылки, статус блокировки.
- Подписки (тариф, срок, лимиты, токен подписки), соответствие аккаунтам на панелях, хеши устройств.
- Платежи, баланс кошелька и журнал операций, промокоды и реферальные записи, заявки на вывод, налоговые чеки, если они включены.
- Обращения в поддержку, история рассылок, журнал аудита действий администраторов (кто что изменил), записи о доставке
  исходящих вебхуков.
- Адреса электронной почты, только у клиентов, выбравших вход в веб-кабинет по почте.
- Резервные копии всего перечисленного (см. [backups.md](backups.md)).

## Прокси для Telegram

MTProto-прокси (telemt) и SOCKS5-инбаунд видят адреса подключающихся на сетевом уровне. Прокси-сервер сам ограничивает число
одновременных исходных IP на аккаунт, чтобы обнаруживать передачу ссылки; Netoryx читает итоговую статистику, меняет ссылку
при злоупотреблении и адреса клиентов не хранит.

## Ваша собственная инфраструктура

У хостинг-провайдера, панели VPN, обратного прокси и Telegram есть свои журналы, на которые Netoryx не влияет. Docker-стек
ротирует логи контейнеров (10 МБ x 3 файла на контейнер). Держите журналирование панелей на минимуме, который вас устраивает.

## Юридические вопросы

Ведение VPN-сервиса может налагать юридические обязанности в вашей стране (хранение данных, регистрация, налоговые чеки).
Netoryx не даёт юридических советов. Параметры `TERMS_URL`, `PRIVACY_URL` и `LEGAL_CONSENT_REQUIRED` позволяют показывать
собственные документы и запрашивать согласие клиентов до начала работы с ботом.
