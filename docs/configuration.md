# Configuration

Netoryx has two layers of settings.

1. **The `.env` file** (`/opt/netoryx/.env` after a standard install). Read at start-up. It holds secrets, addresses and
   the process layout, and it provides the *default* for every other setting.
2. **Runtime settings** in the web admin (**Settings**, `https://<domain>/admin/settings`) and in the bot's admin menu.
   They are stored in the database, encrypted when they are secrets, and take effect without a restart. A value changed
   there overrides the same name in `.env`.

Which is which: a setting is *environment-only* if it is needed before the database exists or describes the process
itself (`BOT_TOKEN`, `DATABASE_URL`, `SECRET_KEY`, `PUBLIC_BASE_URL`, `ADMIN_IDS`, `REDIS_URL`, `WEB_HOST`, `WEB_PORT`,
`LOG_LEVEL`, `ROLE`, `BACKUP_DIR` and the legacy `XUI_*` / `REMNAWAVE_*` bootstrap values). The admin shows those
read-only. Everything else is editable at runtime, and you can leave it out of `.env` entirely.

After editing `.env` apply it with the application container only, which does not interrupt VPN sessions:

```bash
cd /opt/netoryx && docker compose up -d --no-deps app
```

Setting names are case-insensitive in `.env`; lists are comma-separated (`ADMIN_IDS=1,2`). Money is entered in rubles.
`.env.example` in the repository lists the optional settings with comments.

## Required

| Setting | Meaning |
|---|---|
| `BOT_TOKEN` | Token from @BotFather. |
| `ADMIN_IDS` | Telegram IDs of the owners, comma-separated. They get the owner role. |
| `SECRET_KEY` | Encrypts stored secrets and signs tokens. Generated by the installer. **Never lose or change it**: stored panel passwords and API keys become unreadable. It is part of any backup plan. |
| `DOMAIN`, `POSTGRES_PASSWORD` | Used by the Docker stack (`docker-compose.yml`) to derive `PUBLIC_BASE_URL` and `DATABASE_URL`. |
| `APP_MODE` | `shop` (sell subscriptions, default) or `personal` (invites and members, no payments). Switchable later from the admin. |

## The settings that matter most

### Privacy and links

| Setting | Default | Meaning |
|---|---|---|
| `CLIENT_IP_LOGGING` | `off` | `off` keeps no customer IP addresses in logs or the database; `masked` keeps only the network (`203.0.113.x`); `full` keeps them. Rate limits and provider IP checks work in memory either way. See [privacy.md](privacy.md). |
| `REALITY_COMPACT_HELLO` | `true` | Reality links ask clients for a Firefox fingerprint without the post-quantum key share, so the TLS hello fits in one TCP segment. Needed on networks that drop the second segment of a large hello. A per-endpoint override in the admin still wins. See [troubleshooting.md](troubleshooting.md). |
| `SUB_PROFILE_TITLE`, `SUB_ANNOUNCE`, `SUB_UPDATE_INTERVAL_HOURS` | brand name, empty, 12 | What apps show for the subscription and how often they refresh it. |
| `SUB_ROUTING_RU_DIRECT` | `false` | Adds a routing profile that sends Russian sites and IPs directly. |
| `SUB_JSON_ENABLED`, `SUB_JSON_AUTO`, `SUB_JSON_DIRECT_RU`, `SUB_JSON_DIRECT_DOMAINS`, `SUB_JSON_PROXY_DOMAINS` | `true`, `true`, `true`, empty, empty | Happ and v2RayTun get a JSON subscription with an Auto config and Russian domains direct. See [subscriptions.md](subscriptions.md). |
| `SUB_WHITELIST_SEPARATE_URL` | `false` | Serve the "LTE" entries only at `/sub/<token>/wl` instead of in the main subscription. |

### Devices

| Setting | Default | Meaning |
|---|---|---|
| `XUI_DEVICE_LIMIT` | `hwid` | `hwid`: the bot counts devices by the `x-hwid` header that apps such as Happ and v2RayTun send, and 3x-ui gets no limit. `ip`: use 3x-ui's `limitIp`, which only works with Xray's access log on (it records client IPs and visited sites). |
| `HWID_REQUIRED` | `false` | An app that sends no HWID: `false` serves it anyway, `true` shows a notice instead. |
| `HWID_DEVICE_TTL_DAYS` | `30` | Forget devices not seen for this long (`0` = never). |
| `DEVICE_RESET_COOLDOWN_MIN` | `30` | How often a user may reset their devices. |

### Blocking and routing on 3x-ui servers

| Setting | Default | Meaning |
|---|---|---|
| `ADBLOCK_ENABLED` | `false` | Adds an Xray rule sending `geosite:category-ads-all` to the blackhole outbound on every 3x-ui server. Toggling it restarts Xray, so connected users reconnect. Ads inside YouTube videos cannot be blocked this way. Remnawave, Marzban and other panels manage their own Xray config and are not affected. |
| `YOUTUBE_EXIT_ENABLED` | `false` | Send YouTube through a separate exit server (in a country where YouTube shows no ads). If that server is down, YouTube takes the normal route. Which countries are ad-free changes over time, so treat it as best-effort. |
| `YOUTUBE_EXIT_LINK` | empty | Share link of the exit server: `vless://` (Reality or TLS), `socks5://user:pass@host:port` or `ss://`. |
| `YOUTUBE_EXIT_DOMAINS` | `geosite:youtube` | Domains for the exit; you can add `domain:googlevideo.com`. Needs sniffing on the VLESS inbounds, which the bot switches on itself. |

### Telegram proxy

| Setting | Default | Meaning |
|---|---|---|
| `TG_PROXY_ACCESS` | `off` | Legacy. Who gets a personal Telegram proxy: `everyone`, `subscribers` or `off` (see [telegram-proxy.md](telegram-proxy.md)). |
| `TG_ONLY_ENABLED` | `true` | The shared Telegram-only link and its `/tg` page ([telegram-only.md](telegram-only.md)). |
| `TG_ONLY_EXCLUDED_COUNTRIES` | `RU,BY,CN,IR,KP,TM,VN` | Servers in these countries (from the location flag) are not offered for it. |
| `TG_ONLY_ALLOW_UNKNOWN_COUNTRY` | `false` | Also offer servers whose location has no country flag. |
| `TG_ONLY_MONTHLY_LIMIT_GB` | `0` | Monthly traffic limit of the shared client per server (0 = unlimited). |
| `TG_ONLY_DAILY_ALERT_GB` | `50` | Alert admins above this daily traffic of the shared client (0 = off). |
| `TG_SOCKS_ENABLED` | `false` | Legacy. Master switch for SOCKS5 accounts (nothing is shown until a 3x-ui `mixed` inbound is marked as the Telegram SOCKS5 inbound). |
| `TG_PROXY_MAX_SERVERS` | `2` | Proxy servers per user (primary plus backups). |
| `TG_PROXY_ROTATE_COOLDOWN_MIN` | `60` | How often a user may get a new proxy link. |

Full guide: [telegram-proxy.md](telegram-proxy.md).

### Languages and web

| Setting | Default | Meaning |
|---|---|---|
| `DEFAULT_LANGUAGE` | `ru` | Language for new users. |
| `ENABLED_LANGUAGES` | `ru,en,uk,kk,uz,fa,zh` | Languages users can choose; the default is always available. |
| `CABINET_ENABLED` | `false` | The customer area in a browser at `/cabinet`. Needs HTTPS. Login methods: `CABINET_LOGIN_BOT` (default on), `CABINET_LOGIN_TELEGRAM`, `CABINET_LOGIN_EMAIL` (needs `SMTP_*`). See [web-cabinet.md](web-cabinet.md). |
| `WEB_ADMIN_ENABLED`, `MINIAPP_ENABLED` | `true` | Turn the web admin or the Mini App off. |
| `WEB_SESSION_HOURS` | `24` | Web admin session length. |

### Business defaults

`TRIAL_DAYS` (3, `0` disables the trial), `TRIAL_DEVICE_LIMIT`, `TRIAL_TRAFFIC_GB`, `EXPIRY_REMINDER_DAYS` (`3,1`),
`AUTO_RENEW_HOURS_BEFORE`, `MIN_TOPUP_RUB`, `MAX_TOPUP_RUB`, `WELCOME_BONUS_RUB`, `REFERRAL_ENABLED`,
`REFERRAL_REWARD_MODE` (`days`, `balance`, `partner`), `REFERRAL_LEVELS_PERCENT` (`10` or `10,5,2` for several levels),
`WITHDRAWALS_ENABLED`, `GIFTS_ENABLED`, `WINBACK_ENABLED`, `REQUIRED_CHANNEL_ID` (force subscription to a channel),
`BRAND_NAME`, `SUPPORT_URL`, `CHANNEL_URL`, `TERMS_URL`, `PRIVACY_URL`, `LEGAL_CONSENT_REQUIRED`.
Plans, prices and texts are edited in the admin (**Plans**, **Texts**); the first start creates a sample plan.

### Terms of service and privacy policy

Publish your own documents (templates: [privacy policy](legal/privacy-policy-template.md), [terms of service](legal/terms-of-service-template.md);
Russian: [ru/legal](ru/legal/)) at any public URL and connect them:

| Setting | Default | Meaning |
|---|---|---|
| `TERMS_URL` | empty | Link to your terms of service or public offer. Shown on the consent screen and by `/terms`. |
| `PRIVACY_URL` | empty | Link to your privacy policy. |
| `LEGAL_CONSENT_REQUIRED` | `false` | Ask each customer to accept the documents before using the bot (needs `TERMS_URL` or `PRIVACY_URL`). |
| `LEGAL_CONSENT_VERSION` | `1` | Change it (for example to `2`) after you update the documents, and everyone is asked again. |

Keep the documents true to your installation: if you set `CLIENT_IP_LOGGING` to anything but `off`, or enable
the e-mail login of the web cabinet, say so in the privacy policy.

### Operations

| Setting | Default | Meaning |
|---|---|---|
| `DELETE_ORPHAN_CLIENTS` | `false` | Remove panel accounts the bot did not create but that look like its own. Leave off unless you know you need it. |
| `EXPIRED_CLIENT_RETENTION_DAYS` | `30` | Remove expired accounts from panels after this many days. |
| `RECONCILE_INTERVAL_MIN`, `HEALTH_CHECK_INTERVAL_MIN` | `5`, `2` | How often panels are converged and checked. |
| `MONITOR_ALERTS_ENABLED` | `true` | Alerts to admins on high CPU, RAM or disk, stopped Xray, offline nodes. |
| `BACKUP_*` | see [backups.md](backups.md) | Daily backups. |
| `LOG_LEVEL`, `LOG_JSON`, `SENTRY_DSN` | `INFO`, `false`, empty | Logging. |
| `UPDATE_CHECK_REPO` | empty | `owner/name` on GitHub; the admin then shows when a newer release exists. |
| `REDIS_URL` | empty | Optional: FSM storage, throttling and locks shared between processes. |
| `TZ` | `Europe/Moscow` | Time zone for business times (reminders, quiet hours, the backup time). |

Payment settings are described in [payments.md](payments.md).

## Checking the configuration

```bash
cd /opt/netoryx
docker compose exec app /app/.venv/bin/python -m app check
```

It validates the settings, the database and the bot token. `--offline` skips the Telegram call.
