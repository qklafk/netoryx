# Участие в проекте

Спасибо за помощь. Мы рады сообщениям об ошибках, исправлениям, переводам и новым интеграциям платёжных систем и панелей.

## Настройка окружения разработки

Требования: Python 3.12+, [uv](https://docs.astral.sh/uv/), Node.js 20+ для веб-фронтенда.

```bash
git clone https://github.com/qklafk/netoryx.git
cd netoryx
uv sync --all-extras
cp .env.example .env        # укажите BOT_TOKEN (тестового бота) и ADMIN_IDS
uv run python -m app check --offline
uv run python -m app        # бот + веб + фоновые задачи (по умолчанию SQLite)
```

Фронтенд (React, Vite, TypeScript) находится в `web/`:

```bash
cd web
npm ci
npm run dev          # веб-админка на 127.0.0.1 с горячей перезагрузкой
npm run dev:app      # Mini App на порту 5174
npm run typecheck && npm test
npm run build        # собирает web/dist/admin и web/dist/app
```

## Проверки перед pull request

```bash
uv run python -m pytest -q
uv run python -m ruff check app installer tests
uv run python -m ruff format app installer tests
uv run python -m mypy app installer
```

Офлайн-набор тестов занимает несколько минут. Тесты, которым нужен Docker или сеть, пропускаются, пока вы не включите их
переменными `XUI_INTEGRATION=1`, `REMNAWAVE_INTEGRATION=1` или `CORE_DB_INTEGRATION=1`. CI выполняет те же проверки.

## Соглашения по коду

- Длина строки 120, аннотации типов везде, код проходит mypy, короткие docstring, комментарии на английском.
- Деньги хранятся целыми копейками. Любое изменение баланса проходит через `app/services/wallet.py`.
- Время хранится в UTC с указанием часового пояса.
- SQL должен оставаться переносимым между SQLite, PostgreSQL и MySQL: никаких специфичных для диалекта upsert; «вставить,
  если нет» делается через savepoint и `IntegrityError`.
- Функции, принимающие `session`, никогда не делают commit; функции, принимающие `session_factory`, сами владеют короткими
  транзакциями.
- **Никаких сетевых вызовов (Telegram, панели, платёжные API) при открытой транзакции БД.**
- Источник истины о состоянии панелей — база данных; записи в панели идемпотентны.
- Платёж сохраняется до показа ссылки и зачисляется идемпотентно; вебхукам нельзя доверять без проверки подписи или IP и,
  по возможности, повторного запроса данных у провайдера.
- Никаких секретов в логах и журнале аудита. `aiohttp` — единственный HTTP-клиент.
- Новое поведение требует теста. Исправление ошибки требует теста, который без исправления не проходит.
- Новые видимые пользователю строки добавляйте в файлы локализации (как минимум русский и английский).
- Изменения схемы требуют миграции Alembic, которая работает на всех трёх базах данных.

## Коммиты и pull request

Небольшие целостные коммиты с заголовком в повелительном наклонении («Fix renewal of unlimited subscriptions»). Если причина
неочевидна, объясните её в теле коммита. В pull request опишите, как вы проверили изменение. Не коммитьте секреты, настоящие
токены и адреса серверов.

## Лицензия

Netoryx распространяется под лицензией GNU AGPL-3.0-or-later. Код остаётся под AGPL; вклад принимается на условиях
[Соглашения о правах на вклад (CLA)](CLA.ru.md) (юридическую силу имеет английская версия: [CLA.md](CLA.md)).

### Contributor License Agreement (CLA)

Каждый участник подписывает CLA один раз. Это происходит так:

1. Откройте pull request. Бот CLA оставит в нём комментарий со ссылкой на [CLA.md](CLA.md).
2. Прочитайте соглашение и ответьте боту ровно такой фразой: `I have read the CLA Document and I hereby sign the CLA`
3. Бот запишет ваше имя пользователя GitHub и отметит проверку как пройденную. Подпись действует и для ваших следующих pull
   request. Если проверка не обновилась, напишите комментарий `recheck`.

Зачем нужно CLA: оно позволяет мейнтейнеру сохранить возможность предлагать Netoryx по коммерческой лицензии (например,
компаниям, которые не могут выполнять условия AGPL), пока публичный код остаётся под AGPL. Авторские права на ваш вклад
остаются у вас, вы можете использовать его где угодно. Если вы не можете согласиться с CLA, прежде чем писать код, откройте
issue и обсудите это.

## Чек-лист pull request

- [ ] Тесты добавлены или обновлены; pytest, ruff и mypy проходят (см. выше)
- [ ] Видимые пользователю строки находятся в файлах локализации (как минимум русский и английский)
- [ ] Миграция Alembic для изменений схемы, работающая на SQLite, PostgreSQL и MySQL
- [ ] В изменении нет секретов, токенов, адресов серверов и данных клиентов
- [ ] Документация обновлена, если изменилось поведение или настройки
- [ ] CLA подписано

Участвуя в проекте, вы соглашаетесь соблюдать [Кодекс поведения](CODE_OF_CONDUCT.ru.md).
